---
title: Security as a Property of Architecture
sidebar_label: Security as Architecture
description: PTERI security comes from where keys live and what servers can do, not from policy, user education or trust in operators.
---

PTERI security does not depend on:

* Policies
* User education
* Manual review
* Trust in operators

It depends on:

* Where keys live
* What servers can do
* What cryptography allows

> If a system cannot do the wrong thing, it does not need to be trusted.
